# Order Management App

E-commerce web application used by the sales staff of **BuildPro Construction Supplies**, a European chain of construction material stores, to create and view customer orders.

Project PJ6 (Back-end with PHP) - DAW2, Escola del Clot, 2026-27.

## Technologies

| Part | Technology |
|---|---|
| Server side | PHP 8 on Apache (XAMPP) |
| Client side | HTML, CSS and JavaScript (Firefox or Chrome) |
| Data storage | JSON text files |
| Communications | HTTPS (Apache `mod_ssl`) |
| Version control | Git and GitHub |

The client side only works as a user interface: it never stores data and never makes calculations. Prices, VAT and storage are handled by PHP. The client communicates with PHP with `fetch()` (GET for reading operations, POST for writing operations).

## Installation and execution (XAMPP on Windows)

1. Install [XAMPP](https://www.apachefriends.org/) (Apache + PHP 8).
2. Clone the repository inside `C:\xampp\htdocs` with the folder name `orderManagementApp`:
   ```
   cd C:\xampp\htdocs
   git clone https://github.com/IscaviDev/daw2_castillo_isaac_pj6f4a11.git orderManagementApp
   ```
3. Start **Apache** from the XAMPP Control Panel. XAMPP already includes `mod_ssl`, a self-signed certificate for `localhost` and the HTTPS virtual host on port 443 (`apache/conf/extra/httpd-ssl.conf`).
4. Open **https://localhost/orderManagementApp/** in Firefox or Chrome.
   The first time, the browser warns that the certificate is self-signed: choose *Advanced → Accept the risk and continue* (Firefox) or *Advanced → Proceed to localhost* (Chrome).
5. Log in with the user `admin` and its password.

No dependencies need to be installed: the application only uses PHP, HTML, CSS and JavaScript.

### HTTPS

- `.htaccess` redirects every HTTP request to HTTPS (301), so `http://localhost/orderManagementApp/` always ends in `https://`.
- The session cookie is `Secure`, `HttpOnly` and `SameSite=Strict`, so the session only works over HTTPS.
- `users/` and `orders/` cannot be downloaded from the browser (403 Forbidden): only PHP reads them.

## Functionalities

1. **Start**: logo, name of the application, buttons to the documentation and to the log in page.
2. **Description and documentation**: what the application does and how to use every operation.
3. **Authentication**: user name and password. Missing data is controlled by JavaScript; the user is validated by PHP (`password_verify`). If the validation fails, an error message is shown and the user goes back to the start page.
4. **Operations menu**: drop-down list (create a new order / view orders) and a single access button.
5. **Create a new order**: order code, customer data and the 4 products of the catalogue (a checkbox enables the quantity). PHP calculates the total price with 21% VAT, saves the order in `orders.json` and responds only with that result, which the client shows.
6. **Orders view menu**: view all the orders or one order.
7. **View all the orders**: HTML table generated by PHP with all the data of all the orders.
8. **View one order**: the user enters the order code and PHP generates an HTML page with all the data of the order.

## Server API

All the scripts are in `application/server/`.

| Script | Method | Data | Successful response | Error responses |
|---|---|---|---|---|
| `login.php` | POST | `user`, `password` | 200 text | 400 missing data, 401 user not validated, 405, 500 users file not readable |
| `session.php` | GET | - | 200 JSON `{"user": ...}` | 401, 405 |
| `products.php` | GET | - | 200 JSON with the 4 products | 401, 405 |
| `createOrder.php` | POST | `code`, `fullName`, `address`, `email`, `phone`, `quantities[P01..P04]` | 201 text: total with VAT, e.g. `156.44` | 400 invalid data, 401, **404 HTML** orders file not found / not openable, 405, 409 repeated code |
| `showOrders.php` | GET | - | **200 HTML** table | 401, **404 HTML** orders file not found, 405 |
| `showOrder.php` | GET | `code` | **200 HTML** table | 400 invalid code, 401, **404 HTML** order not found, **404 HTML** orders file not found, 405 |

The HTML pages generated by PHP (views and errors) include the buttons *Back to orders view menu*, *Back to operations menu* and *Back to start*.

## Data format

`orders/orders.json` is a JSON object whose keys are the order codes. Every order is a multidimensional associative array:

```json
{
    "ORD-001": {
        "code": "ORD-001",
        "date": "2026-10-20 17:24:46",
        "salesperson": "admin",
        "customer": {
            "fullName": "Núria Puig Soler",
            "address": "Carrer Major 12, 08001 Barcelona",
            "email": "nuria@example.com",
            "phone": "+34600111222"
        },
        "products": {
            "P01": { "name": "Grey cement CEM II/B-L 32.5 N (25 kg bag)", "unitPrice": 3.26, "quantity": 10, "subtotal": 32.6 },
            "P04": { "name": "White matt interior plastic paint (15 L bucket)", "unitPrice": 32.23, "quantity": 3, "subtotal": 96.69 }
        },
        "totals": { "withoutVat": 129.29, "vatRate": 21, "vat": 27.15, "withVat": 156.44 }
    }
}
```

`orders.json` is not included in the repository (`.gitignore`): it is created automatically when the first order is saved.

## How to test

### Normal flow

1. Open `https://localhost/orderManagementApp/` → start page → *Log in*.
2. Log in with `admin` → operations menu → *Create a new order*.
3. Fill in the form, tick some products, enter the quantities and click *Send order*. The total with VAT is shown under the form.
4. Check that `orders/orders.json` has been created with the order.
5. Operations menu → *View orders* → *View all orders*: table with all the orders.
6. *View one order* → enter the order code → table with the order.

### Error control

| Test | Expected result |
|---|---|
| Log in with an empty field | Client message, nothing is sent |
| Log in with a wrong password | Authentication error message and return to the start page |
| Open `menu.html` without logging in | Return to the start page with a "session not active" message |
| New order with empty or invalid fields, or no product ticked | List of errors on the client; the server also validates (400) |
| New order with a code that already exists | Message from the server (409) |
| View all orders before creating any order (no `orders.json`) | 404 HTML error page |
| View one order with a code that does not exist | 404 HTML error page (order not found) |
| Rename `orders.json` and view one order | 404 HTML error page (file not found) |
| Rename the `orders` folder and create an order | 404 HTML error page (file cannot be opened) |
| Open `https://localhost/orderManagementApp/users/users.json` | 403 Forbidden |

The status codes can be checked in the *Network* tab of the browser developer tools (F12), or with `curl`, for example:

```
curl -k -i https://localhost/orderManagementApp/application/server/login.php
curl -k -i -d "user=admin&password=wrong" https://localhost/orderManagementApp/application/server/login.php
```

The first command returns `405 Method Not Allowed` (login only accepts POST) and the second one `401 Unauthorized`.
